# Changelog

Changes of this fork (sandyhq/zend), newest first. Upstream changes are in the git history.

## 2026-11-22

### Fixed
- Phone link security: a linked phone reads only its chats' own folders. A host file outside them by absolute path (file or image) is refused, and so is a chat folder that is the home folder, above it, or holds Zend's data (`ipc-token`, `phone-link-key`, `agent-accounts`), for files, listings, search, watches and attachment chunks (`crates/engine/src/phone_reads.rs`). The computer's own window keeps reading host files read-only.
- Phone link security: the phone and the computer prove the link's key to each other with a challenge (HMAC-SHA256 over fresh nonces, `crates/rpc/src/link_proof.rs`), the computer first, so the key never crosses the wire and an address that answers without it (a wrong DNS answer, a stranger) learns nothing; the phone also dials only tailnet addresses. A phone that sends the key as a bearer is refused: update Zend on the phone with the computer. The v=2 code is unchanged.
- Phone link security: a phone's methods are a list of their own, no longer the agent token's plus a window's: agent accounts, plugin installs and tools, templates and themes made or switched, visuals published and device stats are refused (`crates/rpc/src/remote.rs`). Queueing commands (run, steer, stop, answer) stays: without it a phone can't drive a chat.
- RPC connections abort their calls in flight however they end, also when the connection's task is dropped: a new phone-link key no longer leaves a revoked phone's running calls going (`crates/rpc/src/server.rs`).

### Added
- Phone link over the tailnet (branch direct-link): Settings → Devices → Show code turns on a second listener of the engine on this computer's tailnet address (found with `tailscale status --json`, else an interface in 100.64.0.0/10) and shows a v=2 code (`zend://connect?v=2&host=…&port=…&key=…`, the MagicDNS name or the IP, as chosen there); no relay needed. The phone keeps the desktop (host, port, key; mode 600), runs no engine of its own and drives the desktop's over that link: its sessions, transcripts and sending. The link binds tailnet addresses only, admits tailnet peers only, takes its own key (never the computer's ipc-token) and serves the window's methods only (`Caller::Remote`; no credentials, sign-in, vault or plugin authority); a switch turns it off, New key cuts every phone holding the old one. v=1 relay codes still work.

## 2026-11-21

### Fixed
- Chat: a reply's relative file link written `./plans/x.md` (or with a `..` that stays inside the folder, `plans/a/../x.md`) is read from the session's folder, shown as a file chip and opens in the file viewer; before, anything with a `.` or `..` part was not a link. A path that climbs out of the folder stays no link.

### Added
- Android plugins (branch android-app): Zend's own and installed plugins load from `<files>/.zend/plugins`; the consent sheet opens on the phone (one surface: the newest window holds it) and says under each ask what Android lacks (`commands`, `native`, `files`, `windows`, `web`), which are never granted there and refused with why; Install takes a link only; Appearance and setup have no Frosted glass on Android.
- Android plugins, engine side: what Android lacks is dropped from every plugin's allowed permissions as the engine scans them (`crates/engine/src/plugins/device.rs`), consents made before included, so a service's `zend.run` and the native MCP servers handed to agents hold the same line as the window; the consent sheet words follow the device the plugin is for (its platform, from the window that asks), and a git link on Android fails as `git_unavailable`, said in the phone's words (use a `.zend-plugin` link or a release).
- Plugins: a plugin declined with Not now shows its sheet again from Review (it showed "Nothing to allow"); a failed install or switch in Settings → Plugins says the engine's reason (the toast had only its title); Android's Back closes the consent sheet.
- Android (work in progress, branch android-app): the desktop's interface (apps/zgx) as an APK with no Kotlin or Java, `apps/zgx/android/build-apk.sh` (package `sh.zend.zgx`). zend-zgx is a library with a thin `main.rs`; the APK's NativeActivity runs it with `ui/` and Zend's own plugins unpacked into the app's files folder, and the engine runs inside the app on a thread of its own (data in `<files>/.zend`), served in-process over a socket pair with no port open; an activity made again (rotation, a configuration change) runs a new window loop against the same engine, and Back is Escape. Release APKs are not debuggable and keep the app's tokens out of backups (`apps/zgx/android/README.md`). The edge comes from `<files>/.config/zend/edge-url` and `edge-token` as on the desktop fork; without them the app runs offline. The status, navigation and keyboard bars reach the interface as `ui.shared("system.insets")` (`@ds/insets`). Harness installs are off on Android, and the engine's create-once files use `renameat2(RENAME_NOREPLACE)` there in place of link(2), which the app sandbox refuses. portable-pty is now 0.9 (no termios patch).
- Android: desktop-only parts gated or replaced (`@ds/platform`: `has`/`check`). Links and files open in their app through an intent, copy and paste go through Android's clipboard, notifications post to Android's shade (POST_NOTIFICATIONS asked for); dictation, the terminal, the browser panel, App shots, Reveal/Open outside, file pickers and the updater are hidden there (settings pages, their search rows, the panel's Open list, `/terminal`, the composer's mic and +).
- Connect a phone by QR code (Settings > Devices, branch android-app): on a computer, Show code draws a QR code holding this computer's edge URL and its own edge bearer (`zend://connect?v=1&edge=…&token=…`, `src/phone_link.rs`), shown for 60 s or until Hide; with no relay set it says so. On Android, Scan code reads it with the NDK camera (camera2ndk + AImageReader, decoded with rqrr, the permission asked over JNI, no Kotlin; `src/android_camera.rs`) or its text is pasted; the code is checked strictly first (an http(s) URL with a host and no userinfo, path or query; nothing from it reaches the log), the app keeps edge and bearer as one record `<files>/.config/zend/edge` (0600, written atomically) and starts its engine again on the new edge with no app restart, rolling back if that fails, and says Connected only once the relay answers. A fresh install starts onboarding with Connect to a computer. `phone.*` actions are refused in plugin previews and not exposed to plugins.
- Compact window (under 600 pt wide, a phone's): the sidebar opens as a drawer over the page (title bar toggle, a swipe in from the left edge; a tap beside it, a swipe back, Escape or going anywhere closes it), the panel opens as a sheet over the page, Settings shows its list or one page with a Settings back button (Escape goes back to the list first), the title bar's controls are 44 pt touch targets without Forward, and the palette's scope row drops its Tab hint. Wider windows are unchanged.
- Ideas & Intents: a page of its own under Search in the desktop sidebar for typed ideas (no title, project or chat) and voice memos, newest first, kept on this device in `<data>/ideas`. A memo is recorded between Record and Stop (at most a minute), written to disk as a WAV before it is transcribed with the local speech model, plays after a restart, and keeps its audio when there is no model or transcription fails. Leaving the page stops and saves a recording (one still starting is dropped); a failed Save keeps the draft. While a memo records, dictation's live waveform shows what the microphone hears. The composer's dictation still keeps no audio.

### Changed
- Idle stop (from upstream): a parked agent whose chat shows a visual still waiting on the person's answers (inputs, not sent, not dismissed) is not stopped; it stops once they are sent or the visual is dismissed, as after a question.

### Fixed
- Engine: a Stop sent just after a steer is no longer dropped as aimed at a finished turn when the steer lands first; it stops the turn, steer included (`runtime_survival::a_steer_sent_before_stop_is_cancelled_with_it`). A Stop now names the sends it stops (`Interrupt.cancels`, ADR 0007) and the host decides by that, not by clocks or ledger order: across devices and by relay a send named by a Stop never runs after it, and a late Stop never stops a turn its sender didn't know of. What a Stop names stays cancelled when the Stop itself is moot or gives way to a newer one, and across a restart of the host; a Stop waits for no send (a named one checks the names as its last step before the agent, a revival after a restart too) and kills only a runtime handed nothing its sender never saw, decided and retired in one step (`runtime_survival::a_named_send_stalled_before_its_runtime_never_starts`, `a_stuck_queue_send_does_not_hold_up_the_stop_naming_it`, `run_recovery::a_turn_a_stop_named_is_not_revived_after_shutdown`); one aimed at a turn a rewind removed is moot. A Stop from an older engine keeps the old rule. A send its sender had seen (its row up to the Stop's turn) is claimed like a named one, every road to the agent asks one check that reads disk and memory (a queue row sent now after a restart too), and a runtime remembers every message it was handed, with no count (`runtime_survival::a_queue_row_a_stop_named_is_not_steered_in_after_a_restart`, `a_send_the_stops_sender_saw_stalled_before_its_runtime_never_starts`, `a_stop_leaves_a_runtime_handed_an_unseen_message_before_256_named_ones`). A send a Stop claims while its run is preparing never reaches the harness, and the Stop doesn't wait for the preparation; the turn a Stop was aimed at is claimed even before its row reaches the host (`a_send_a_stop_claims_while_it_prepares_never_reaches_the_harness`, `a_queue_row_a_stop_was_aimed_at_is_not_steered_in_after_a_restart`). A Stop carries its sender's doc version (`based_on.frontier`), and what its sender saw is the rows that version holds, not the rows before its turn in the host's order: a turn started after the Stop was built is never killed or claimed by it, wherever the merge puts it; the version is read back from the doc, or from the ledger for a relayed Stop, after a restart; the per-send check is a lookup instead of a transcript walk (`a_stop_spares_a_turn_its_sender_never_saw_merged_before_its_aim`, `a_stops_version_is_read_back_from_the_doc_after_a_restart`). Whether that version held a row is read from the doc's ops (the one that gave the row its id, the ones that removed it), not from the row's map: a send the Stop saw stays stopped after its row is rewound and the host restarts, and when its row's id reaches the host after the Stop; a send whose empty row the sender held before it had an id runs (`a_send_a_stop_saw_stays_claimed_once_its_row_is_rewound_and_the_host_restarts`, `a_send_a_stop_saw_is_claimed_when_its_rows_id_arrives_after_the_stop`, `a_stop_built_before_a_row_had_its_id_lets_that_send_run`, `zend-doc stop_version`). The window's Stop says the version of the transcript it shows, not of the doc, which may hold an import not shown yet (`zend-client a_stop_says_the_version_of_the_transcript_it_was_pressed_on`), and an engine Stop whose caller named its sends carries its version too (`an_engine_stop_with_its_sends_named_says_its_version`).

## 2026-11-16

### Added
- Visuals: the window asks the chat's host which visuals are open (new read-only RPC `ListOpenVisuals {chatId}`, forwardable like `MarkVisualSent`; a host without it answers unknown method and the transcript's own visuals still pin), so an open visual is pinned before a long chat's history has loaded, and only visuals that ask something are ever opened for the pin.
- Visuals: an open visual is pinned above the composer whenever its place in the transcript is not in view, also when that place was never built (a long chat opened at the bottom, a chat opened again); it goes only when answered or closed with ×.
- Chats: Auto access mode (ported from upstream) lets the agent's own reviewer approve safe actions and ask about risky ones; Claude Code and Codex offer it, other agents don't. When Auto is unavailable for a chat the composer holds Send and says why; the engine refuses the run rather than falling back to a looser mode.
- Chats: Edit on your own prompt (removes it and everything below, after one confirmation, then sends the edited words; the agent starts a fresh session fed the kept history) and Fork from here on any prompt or reply (`RewindChat`, `ForkSideChat` `messageId`).
- Transcript: every tool's row opens to what it did, by kind (a read's picture or coloured lines, an edit's diff, codemode's script and result, an MCP tool's args and result), read from the host's run journal (`ReadToolExchange`, `ReadToolImageChunk`); a chevron shows a row opens; pi's edits carry their diff, codex's one-file changes their patch (`FileUpdateChange.diff`, v2's `kind: {type}` read too).
- Engine: a read's picture is the bytes its result gave the agent (`AgentEvent::ToolImage` from pi and Claude Code, ≤10 MB, kept beside the journal), never the file at its path when the row opens.
